 版本號在建置時透過 -ldflags "-X main.version=$(VERSION)" 注入。

 ────────────────────────────────────────────────────────────────────────────────

 如何更換版本號

 ### 方式 1：單次建置指定版本（推薦、不改檔案）

 ```bash
   # 開發建置
   make build VERSION=2.2.0

   # 發布建置（CGO-free 單一執行檔）
   make build-release VERSION=2.2.0

   # 完整發布檢查
   make release-check VERSION=2.2.0
 ```

 ### 方式 2：永久修改預設版本（修改兩處）

 1. 編輯 cmd/mcp-server/main.go：
    ```go
      var version = "2.2.0" // 改這行
    ```
 2. 編輯 Makefile：
    ```makefile
      VERSION ?= 2.2.0  # 改這行
    ```

 ### 方式 3：直接 go build

 ```bash
   go build -ldflags "-X main.version=2.2.0" -o bin/tw-quant-mcp ./cmd/mcp-server
 ```

 GitHub Release 的觸發機制

 此專案的 .github/workflows/release.yml 只有 一種 觸發方式：

 ```yaml
   on:
     push:
       tags:
         - "v*"
 ```

 必須推送 git tag（格式 v*）才會觸發 GitHub Actions 自動發布。

 ────────────────────────────────────────────────────────────────────────────────

 正確的發布流程

 ```bash
   # 1. 確認 main.go 與 Makefile 的版本號一致（或只靠 tag 覆寫）
   #    目前 main.go 是 2.1.0，Makefile 預設 2.1.0

   # 2. 建立並推送 tag（版本號取自 tag，而非 Makefile）
   git tag v2.2.0
   git push origin v2.2.0

   # 3. GitHub Actions 自動執行：
   #    - test → build（多平台，ldflags 注入 ${TAG} 即 "v2.2.0"）
   #    - 建立 GitHub Release（標題 "tw-quant-mcp v2.2.0"）
   #    - 上傳 5 平台 artifacts + checksums.txt
   #    - （可選）更新 Homebrew tap（需 TAP_TOKEN secret）
 ```

 關鍵細節

 ┌─────────────────────────────────┬──────────────────────────────────────────────┐
 │ 位置                            │ 版本號來源                                   │
 ├─────────────────────────────────┼──────────────────────────────────────────────┤
 │ 本地 make build VERSION=...     │ Makefile 的 VERSION 變數                     │
 ├─────────────────────────────────┼──────────────────────────────────────────────┤
 │ 本地 go build -ldflags ...      │ 你手動給的 -X main.version=...               │
 ├─────────────────────────────────┼──────────────────────────────────────────────┤
 │ GitHub Actions Release workflow │ Git tag（${{ github.ref_name }}，如 v2.2.0） │
 └─────────────────────────────────┴──────────────────────────────────────────────┘

 │ ⚠️ 注意：GitHub Actions 的 build 步驟用的是 tag 名稱（含 v 前綴），會直接注入 main.version=v2.2.0。如果你希望二進制裡的版本號不
 │ 含 v，需修改 workflow 的 -ldflags 為 -X main.version=${TAG#v}。

 總結

 ┌──────────────────────────────────────────┬─────────────────────────────────┬───────────────────────┐
 │ 操作                                     │ 影響本地 binary 版本            │ 影響 GitHub Release   │
 ├──────────────────────────────────────────┼─────────────────────────────────┼───────────────────────┤
 │ make build VERSION=2.2.0                 │ ✅ 是                           │ ❌ 否                 │
 ├──────────────────────────────────────────┼─────────────────────────────────┼───────────────────────┤
 │ 修改 main.go / Makefile                  │ ✅ 下次 build                   │ ❌ 否                 │
 ├──────────────────────────────────────────┼─────────────────────────────────┼───────────────────────┤
 │ git tag v2.2.0 && git push origin v2.2.0 │ ❌ 否（除非你在 CI 環境 build） │ ✅ 是（唯一觸發方式） │
 └──────────────────────────────────────────┴─────────────────────────────────┴───────────────────────┘

 要發布新版，只需推 tag；本地修改版本號僅供開發/測試用。
